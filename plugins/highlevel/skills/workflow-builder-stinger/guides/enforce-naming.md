# Enforce Naming Conventions

Grounding: `references/research/distilled-research-article.md` section 5, from raw/04 (see the source table in the distillation).

Naming is something she struggles with, and every AI proposing a different system is the problem this guide stops.

## Rules

1. Read `Naming Conventions.md` fresh before naming anything. Only the `## Decided` section counts.
2. Anything marked "Superseded" lower on the page is dead. Never use it, never offer it as an option.
3. **Never suggest a new naming system, a tweak to a decided pattern, or "a cleaner alternative."** Not even as an aside.
4. Apply the decided pattern exactly, including separators and spacing. Fill each slot with plain words a low-tech client would understand.
5. Name everything the build creates that has a decided pattern: workflows, email templates, appointment titles, email subjects.

## When the rules do not cover it

- The item has no decided pattern, or it sits in `## Conflicts to decide`: **do not pick one.**
- Ask her **one** question. Offer the existing candidates from the page (up to 3), not new ones.
- After she answers:
  1. Add her answer under `## Decided` as `- **{Item} (decided YYYY-MM-DD):** {pattern}. Example: {example}. Why: {her reason, or omit if not said}`.
  2. If it resolved a numbered conflict, mark that conflict `RESOLVED YYYY-MM-DD` in place, as the page already does.
  3. Capture the decision in the Logic Log (guide: `capture-to-logic-log.md`).
- If she wants to keep going before deciding, use a clearly temporary name (`TEMP - ...`) and list it under Open questions in the build sheet.

## Reviewing existing names

When reviewing a workflow, compare its name to the decided pattern and report a mismatch with the corrected name. Do not rename anything in an account yourself.
